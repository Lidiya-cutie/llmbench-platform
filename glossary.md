# Глоссарий

Термины и определения, используемые в платформе llmbench.

---

## Бенчмаркинг

| Термин | Определение |
|---|---|
| **MMLU-Pro** | Расширенный бенчмарк знания и рассуждения (12000 вопросов, 120 категорий). Наследник MMLU с усложнёнными вопросами и 10 вариантами ответов вместо 4. |
| **GSM8K** | Grade School Math 8K — бенчмарк решения школьных математических задач (8500 задач). Проверка многошаговых рассуждений. |
| **Minerva Math** | Математический бенчмарк от Google Minerva (9 категорий: algebra, geometry, number theory и др.). |
| **HumanEval** | Бенчмарк генерации кода (164 задачи на Python). Оценка через выполнение unit-тестов. Метрика: pass@1. |
| **MBPP** | Mostly Basic Python Problems — 974 задачи на программирование на Python. Метрика: pass@1. |
| **GPQA** | Graduate-Level Google-Proof Q&A — бенчмарк вопросов аспирантского уровня по физике, химии, биологии. |
| **IFEval** | Instruction Following Evaluation — бенчмарк следования инструкциям (строгие и мягкие критерии). |
| **DocVQA** | Document Visual Question Answering — визуальный вопрос-ответ по документам (изображения). |
| **OCRBench** | Бенчмарк оптического распознавания символов на изображениях. |
| **ChartQA** | Вопрос-ответ по графикам и диаграммам. |

## Метрики

| Термин | Определение |
|---|---|
| **accuracy** | Доля правильных ответов в задачах множественного выбора. Диапазон: [0, 1]. |
| **acc_norm** | Нормализованная accuracy — доля правильных ответов с нормализацией по длине ответа. |
| **pass@1** | Вероятность корректного решения задачи с одной попытки генерации кода. |
| **strict-match** | Строгий режим сверки ответа: точное совпадение с эталоном (например, для математики). |
| **flexible-extract** | Гибкий режим извлечения ответа: числовое значение извлекается из свободного текста ответа. |
| **TTFT** | Time To First Token — время от отправки запроса до получения первого токена (секунды). |
| **tok/s** | Tokens per second — скорость генерации токенов (токенов в секунду). |
| **latency p99** | 99-й перцентиль задержки ответа на запрос (секунды). |
| **prefill_tok/s** | Скорость обработки prompt (prompt prefill), токенов в секунду. |

## Инфраструктура

| Термин | Определение |
|---|---|
| **vLLM** | Высокопроизводительный inference-сервер для LLM. Поддерживает PagedAttention, continuous batching. Форматы: BF16, FP16, AWQ, GPTQ. |
| **lm-eval-harness** | EleutherAI lm-evaluation-harness — фреймворк для оценки LLM на стандартных бенчмарках. Версия: 0.4.12. |
| **VLMEvalKit** | Фреймворк для оценки vision-language моделей (VLM). Интегрирован в llmbench для DocVQA, OCRBench, ChartQA. |
| **Triton Inference Server** | NVIDIA Triton — inference-сервер для production. Поддерживает TensorRT, PyTorch, Python backends. |
| **SGLang** | Альтернативный inference-сервер. Оптимизирован для structured generation. |
| **Ollama** | Локальный inference-сервер. Упрощённое управление моделями в формате GGUF. |
| **llama.cpp** | C++ inference-движок. Поддерживает GGUF, ternary (1.58-bit), квантизацию. Оптимизирован для CPU и GPU. |
| **MLflow** | Платформа управления жизненным циклом ML-моделей. Используется для трекинга экспериментов. |

## Развёртывание

| Термин | Определение |
|---|---|
| **GPU** | Graphics Processing Unit — графический процессор. В контексте llmbench: NVIDIA GPU с поддержкой CUDA. |
| **VRAM** | Video RAM — видеопамять GPU. Основной ресурс для размещения весов модели и KV-cache. |
| **BF16** | BFloat16 — 16-битный формат чисел с плавающей точкой. Стандарт для inference LLM. |
| **FP16** | Float16 — 16-битный формат с плавающей точкой. Меньший диапазон, чем BF16. |
| **AWQ** | Activation-aware Weight Quantization — метод 4-битной квантизации весов с сохранением точности. |
| **GPTQ** | Метод посттренировочной квантизации LLM (обычно 4-bit). |
| **GGUF** | GGML Universal Format — формат хранения квантизованных моделей для llama.cpp. Варианты: Q2_K — Q8_0. |
| **Ternary (1.58-bit)** | Квантизация до трёх значений (-1, 0, 1). Экстремальное сжатие (например, BitNet b1.58). |
| **KV-cache** | Кэш key-value пар для attention-механизма. Занимает VRAM пропорционально длине контекста. |
| **PagedAttention** | Механизм vLLM для эффективного управления KV-cache (как virtual memory для токенов). |
| **Continuous batching** | Динамическое формирование батчей в vLLM — новые запросы добавляются без ожидания завершения батча. |

## Карточка модели

| Термин | Определение |
|---|---|
| **Model Card** | Структурированный отчёт о модели: качество, производительность, железо, стоимость, заключение. Форматы: JSON + Markdown. |
| **Suite** | Набор бенчмарков для оценки. Варианты: `smoke` (быстрый), `simplified` (основной), `full` (полный). |
| **Checkpoint** | Сохранённое состояние оценки. Позволяет возобновить процесс после сбоя без потери прогресса. |
| **Use-case preset** | Набор весов для скоринга моделей по приоритетам: balanced, coding, reasoning, math, speed, cost. |
| **Baseline** | Модель отсчёта для сравнительного анализа. Все остальные модели сравниваются с baseline. |
